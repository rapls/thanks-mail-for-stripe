PLUGIN

Thanks Mail for Stripeは、Stripe Payment Linksでの購入完了時に自動でサンクスメール（お礼メール）を送信するWordPressプラグインです。 Zapier、Make、IFTTTなどの外部サービスは不要で、Stripeのwebhookを直接受信してメールを送信します。デジタル商品の販売、ソフトウェアライセンスの発行、サービス予約の確認など、様々なシーンで活用できます。 ダウンロード： WordPress.org プラグインページ 管理画面の「プラグイン」→「新規追加」で「Thanks Mail for Stripe」を検索してもインストールできます。

DEMO

Stripe Payment Linkで決済が完了すると、自動的にサンクスメールが送信されます。 テンプレートごとにPayment Link IDを紐付けておけば、どのリンクから購入されたかを自動判定して適切なテンプレートでメールを送信します。テンプレートは最大100個まで登録でき、カテゴリ分けや検索で目的のテンプレートをすぐに探せます。

INSTALLATION

  1. プラグインをダウンロードし、/wp-content/plugins/ディレクトリにアップロードします
  2. WordPress管理画面の「プラグイン」メニューからプラグインを有効化します
  3. 「設定」→「Thanks Mail for Stripe」で各種設定を行います
  4. 表示されるWebhook URLをStripeダッシュボードに登録します
  5. Webhook署名シークレットとPayment Link IDを設定します
  6. テストメールを送信して動作を確認します
サーバー要件：
  • WordPress 5.0以上
  • PHP 7.4以上
  • SSL証明書（HTTPS必須）
  • SMTPプラグイン推奨（メール到達率向上のため）

FEATURES

1. Webhook経由の自動メール送信

Stripeからwebhookイベント（checkout.session.completed）を受信すると、自動的にサンクスメールを送信します。外部サービスは一切不要です。コンビニ決済のように支払いが後から確定する決済方法では、入金が確定した時点（checkout.session.async_payment_succeeded）で送信します。

2. 可変テンプレート（最大100個）

メールテンプレートを最大100個まで自由に追加・削除できます。各テンプレートには名前、カテゴリ、言語（locale）、Payment Link ID、件名、本文を設定できます。 テンプレートが増えても管理しやすいように、次の機能があります。
  • カテゴリ：カテゴリ一覧を作って各テンプレートに割り当て。カテゴリ名を変えると、割り当て済みの全テンプレートに反映されます
  • 検索：名前・カテゴリ・言語・Payment Link ID・件名・本文から検索
  • カテゴリでの絞り込み、1ページ10件のページ送り
  • 折りたたみ／展開（すべて展開・すべて折りたたむ）
  • 「↑」「↓」ボタンでの並べ替え、ワンクリックでの複製
  • 件名と本文だけを、テンプレートの言語に合わせた初期文面に戻すボタン

3. Payment Link IDによるテンプレート自動判定

各テンプレートにStripe Payment Link IDを紐付けておくことで、どのリンクから購入されたかを判定し、適切なテンプレートでメールを送信します。 使われるテンプレートは次の順に決まります。
  1. Payment Link IDが一致するテンプレート
  2. なければ、Checkout Sessionのlocaleと言語が一致する最初のテンプレート（日本語以外はENとして扱います）
  3. それもなければ、一番上のテンプレート
Payment Linksでは決済画面の言語が「自動（auto）」のままになっていることが多く、2のlocale判定はほとんど効きません。確実に出し分けたい場合は、Payment Linkごとにテンプレートを用意してIDを登録してください。

4. 二重送信防止（冪等性）

StripeはWebhookをリトライしたり、同じイベントを複数回送ったりすることがあります。同じ決済に対して複数回メールを送信しないよう、送信前にCheckout Session IDをデータベースに登録して重複を防止します。同じイベントがほぼ同時に2回届いた場合でも、送られるのは1通だけです。 メール送信に失敗した場合は記録を残さないので、Stripeダッシュボードからイベントを再送すれば送り直せます。

5. Webhook署名検証

Stripeから送られてくるWebhookが本物かどうかを、HMAC-SHA256署名で検証します。なりすましリクエストはここで拒否されます。署名の検証に何度も失敗するIPアドレスには、一時的に429（Too Many Requests）を返します。Stripeからの正規の通知はこの制限の対象になりません。

6. テストメール機能

設定が正しく動作するか、実際にテストメールを送信して確認できます。テスト決済をしなくても動作確認が可能です。 テストメールには、画面に表示されているテンプレートの件名と本文がそのまま使われます。保存前の編集内容や、追加したばかりのテンプレートも確認できます（ブランド名・送信元・返信先は保存済みの設定が使われます）。

7. 無料購入への送信（オプション）

100%割引のクーポンコードや無料トライアルのように、支払いが発生しなかった購入にもサンクスメールを送るかどうかを選べます。初期設定ではオフです。

8. 個人データのエクスポート・削除

送信履歴に保存された顧客のメールアドレスなどは、WordPress標準の「ツール」→「個人データのエクスポート」「個人データの消去」で扱えます。

送信元メールアドレスの重要な注意

送信元メールアドレスには、必ず自分のドメインのメールアドレスを設定してください。
  • OK： info@yoursite.com, support@yoursite.com
  • NG： yourname@gmail.com, yourname@yahoo.co.jp
Gmailなどのフリーメールを送信元に設定すると、メールが届かない原因になります。 理由：サーバーからGmailアドレスを名乗ってメールを送信すると、受信側のメールサーバーが「なりすまし（spoofing）」と判断します。
  • SPF認証失敗：GmailのSPFレコードがあなたのサーバーを許可していない
  • DKIM認証失敗：Gmailの署名キーで署名されていない
  • DMARC：Gmailの厳格なポリシーにより拒否/スパム扱い
返信先メールアドレス（Reply-To）は配信に影響しないため、Gmailなどを設定しても問題ありません。

メールテンプレート

テンプレートは管理画面から動的に追加・削除でき、最大100個まで設定可能です。各テンプレートには以下を設定します。
設定項目 説明
名前 テンプレートの識別名（例：No.1, No.2）
カテゴリ 「カテゴリ」欄で作ったカテゴリから選択（任意）
言語（Locale） JA / EN を選択。Payment Link IDにマッチしない場合のフォールバック判定に使用

  • {brand} - ブランド名（設定で指定）
  • {session_id} - Checkout Session ID（照合用）
  • {email} - 顧客のメールアドレス

STRIPE SETUP

Webhookエンドポイントの登録

  1. Stripeダッシュボードにログイン
  2. Developers → Webhooksを開く
  3. Add endpointをクリック
  4. Endpoint URLにプラグイン設定画面のURLを貼り付け https://あなたのドメイン/wp-json/thanks-mail/v1/webhook
  5. 以下のイベントを選択：
    • checkout.session.completed
    • checkout.session.async_payment_succeeded
  6. Add endpointで保存
  7. Signing secret（whsec_...）をコピーしてプラグインに設定

Payment Link IDの確認方法

StripeダッシュボードでPayment Linkの詳細を開くと、URLにplink_...というIDが含まれています。
  • テスト：https://dashboard.stripe.com/test/payment-links/plink_XXXXXXXX
  • 本番：https://dashboard.stripe.com/payment-links/plink_XXXXXXXX
このplink_XXXXXXXXがプラグインに入力するIDです。

TROUBLESHOOTING

Webhookが403エラーになる

セキュリティプラグインやサーバーのWAFがWebhookリクエストをブロックしている可能性があります。 Wordfenceの場合：
  1. Firewall → All Firewall Options → Allowlisted URLsを開く
  2. Webhook URLのパス（/wp-json/thanks-mail/v1/webhook）を追加
エックスサーバーの場合：
  1. サーバーパネル → WordPressセキュリティ設定を開く
  2. 「REST API アクセス制限」をOFFにする
この設定は海外IPからのREST APIアクセスを制限するもので、Stripeからのリクエストもブロックされてしまいます。

Webhookは200なのにメールが届かない

Stripeダッシュボードで{"sent": true}と表示されているのにメールが届かない場合、以下を確認してください。 1. 送信元メールアドレスを確認 送信元メールアドレスにGmailなどのフリーメールを設定していませんか？必ず自分のドメインのメールアドレス（例：info@yoursite.com）を設定してください。詳しくは上記「送信元メールアドレスの重要な注意」を参照してください。 2. 二重送信防止機能 「最近の送信履歴」を確認してください。同じSession IDがすでに記録されている場合、二重送信防止機能が働いています。これは正常な動作です。 3. 無料の購入ではないか 100%割引クーポンや無料トライアルの購入は、初期設定ではメールを送りません（Stripeのレスポンスはno_payment_required_skipped）。送りたい場合は設定の「無料の購入」をオンにしてください。 4. SMTPプラグインの導入 上記を確認しても届かない場合は、SMTPプラグイン（WP Mail SMTPなど）を導入して、メール送信の信頼性を向上させてください。

Webhookが429エラーになる

署名の検証に失敗したリクエストが、同じIPアドレスから1分間に10回を超えると429を返します。Webhook署名シークレットが正しいか（テスト用とLive用を取り違えていないか）を確認してください。

テスト環境と本番環境の切り替え

Stripeのテストモードと本番モードでは、以下の値がすべて異なります。
  • Webhook署名シークレット（whsec_...）
  • Payment Link ID（plink_...）
本番環境に切り替える際は、必ずこれらの値をLive用のものに更新してください。また、StripeダッシュボードのWebhook設定も、テスト用とLive用で別々に登録が必要です。

FILTERS

プラグインの動作をカスタマイズするためのフィルターフックが用意されています。

メールヘッダーのカスタマイズ

CCやBCCを追加する例： 
add_filter( 'tmfs_email_headers', function( $headers, $to, $lang, $session_id ) {
    $headers[] = 'Cc: sales@example.com';
    return $headers;
}, 10, 4 );

テンプレート判定のカスタマイズ

メールアドレスのドメインでテンプレートを切り替える例です。戻り値はテンプレートのインデックス（文字列）で、'0'が一番上のテンプレート、'1'が2番目です。'ja'や'en'を返すと一番上のテンプレートになるので注意してください。 
add_filter( 'tmfs_detect_language', function( $lang, $session ) {
    $email = strtolower( $session['customer_details']['email'] ?? '' );
    if ( substr( $email, -3 ) === '.jp' ) {
        return '1'; // 2番目のテンプレートを使用
    }
    return $lang; // それ以外は通常の判定結果のまま
}, 10, 2 );
インデックスは並び順で決まるため、管理画面でテンプレートを並べ替えると指す先が変わります。

利用可能なフィルター一覧

  • tmfs_email_headers - メールヘッダーの変更
  • tmfs_email_subject - 件名の変更
  • tmfs_email_body - 本文の変更
  • tmfs_detect_language - テンプレート判定ロジックの変更（戻り値はテンプレートインデックス）

DATABASE

カラム 型 説明
id BIGINT 自動採番ID
session_id VARCHAR(255) Checkout Session ID（ユニーク）
email VARCHAR(255) 顧客メールアドレス
lang VARCHAR(8) 使用したテンプレートのインデックス（"0"が一番上）
product_name VARCHAR(255) 予約カラム（現在は常に空）

テーブルが存在しない場合（ネットワーク有効化後に追加したマルチサイトのサブサイトなど）は、プラグインの読み込み時に自動で作成されます。 特定の顧客のデータは「ツール」→「個人データの消去」で削除できます。ただし削除するとその購入の二重送信防止も外れるため、Stripeからイベントを再送するとメールがもう一度送られます。 プラグインをアンインストールすると、このテーブルと設定データは自動的に削除されます。
